## 1. 系统概述

### 1.1 产品定位

XX书店活码管理平台是一套面向教育书店的企业微信私域运营工具，帮助书店通过「活码」将家长引流至企业微信，并由接待员自动分配、服务老师承接转化，完成从「扫码添加 → 表单收集 → 在职继承 → 长期服务」的完整链路。

### 1.2 角色定义

| 角色 | 说明 |
|------|------|
| **管理员 (admin)** | 全部功能访问权限，可管理系统用户、全局配置 |
| **运营人员 (operator)** | 日常运营操作权限，管理活码、员工、客户 |
| **接待员 (receptionist)** | 企微员工，负责首次接待扫码客户 |
| **服务老师 (service)** | 企微员工，负责客户长期服务与转化 |
| **双重角色 (dual)** | 同时承担接待与服务职责 |

### 1.3 核心业务流程

```
家长扫码 → 企微添加接待员 → 自动打标签/发欢迎语
    → 推送收集表单（可选）→ 家长填写→自动打标/备注
    → 在职继承：接待员将客户转移给服务老师
    → 服务老师发送交接问候 → 长期服务
```

## 2. 模块一：活码管理

### 2.1 模块概述

活码（QR Code）是系统的核心资源，每个活码对应一所学校和一组接待员工。客户扫描活码后，系统自动将其分配给该活码绑定的接待员。

### 2.2 活码创建

**功能点：**

1. **手动创建活码**
   - 填写学校名称 → 自动生成 `school_id`（企微 state 唯一标识）
   - 选择所在城市/区县（前端级联下拉选择）
   - 学校名称重复校验（前端 AJAX + 后端唯一约束）
   - 配置企微联系我 `config_id` 和二维码 URL
   - 选择场景：日常推送（daily_push）/ 家长会（parent_meeting）
   - 选择所属企微部门（用于扩容时同部门优先取人）
   - 配置轮换模式：自动轮转（auto）/ 手动指定（manual）
   - 配置预警/紧急阈值（默认 80% / 95%）
   - 配置欢迎语（文字内容）
   - 配置在职继承问候语（4 项：启用开关、已填写备注、已填写问候、未填写问候）
   - 配置转接成功通知消息
   - 关联收集表单模板
   - 配置自定义标签（扫码自动打标）
   - 配置初始上码人数
   - 设置学校学生人数（自动计算接待员数量）
   - 上传/拖拽二维码图片
   - 样式配置：Logo、主题色、文字内容、字体大小

2. **批量导入活码**
   - 下载 Excel 导入模板
   - 上传填写好的 Excel 文件
   - 实时显示导入进度（htmx 轮询进度条）
   - 导入结果反馈（成功数 / 跳过数 / 失败明细）

3. **活码图片合成**
   - 基于企微原始二维码，叠加样式配置（Logo、文字、主题色）
   - 自动生成带品牌标识的活码图片
   - 支持服务器端字体渲染

4. **场景化自动计算**
   - `daily_push`（日常推送）：预估扫码率 20%，紧急阈值 95%，系统自动计算初始接待员人数 = 学生人数 × 20% ÷ 日上限
   - `parent_meeting`（家长会）：预估扫码率 75%，紧急阈值 70%，适合高并发场景
   - 切换场景时自动重新计算接待员人数

### 2.3 活码列表与搜索

**功能点：**

1. **活码列表页**
   - 分页展示所有活码（学校名、区域、状态、接待员数、客户数）
   - 多维度筛选：按城市、区县、状态、轮换模式、场景、分组、学校分类
   - 关键词搜索（学校名称模糊匹配）
   - 批量操作入口
   - 列表数据导出 Excel

2. **活码树形视图**（API）
   - 按区域层级（城市 → 区县 → 学校）返回 JSON 树
   - 活码状态颜色标记（绿/黄/红/灰）

### 2.4 活码详情

**功能点：**

1. **基本信息**
   - 查看/编辑学校名称、区域、企微配置、欢迎语、样式配置
   - 查看/修改轮换模式
   - 查看/修改预警阈值（预警 % / 紧急 %）
   - 查看/修改场景类型

2. **接待员管理**
   - 查看当前上码员工列表（姓名、角色、日上限、今日已添加、状态、优先级）
   - 添加接待员（从全局员工池 / 直接输入 userid）
   - 移除接待员（支持记录移除原因）
   - 调整接待员日上限和优先级
   - 批量回收接待员（将指定员工在本活码下替换为备选）
   - 备选员工管理：添加备选、移除备选、将备选转正

3. **继承转移**
   - 查看待继承客户列表（预览模式，含填写状态）
   - 预览继承匹配结果（客户 → 目标老师）
   - 一键触发全部继承
   - 选择性继承（勾选客户后触发）
   - 补录历史客户到继承表
   - 查看批量转移任务状态
   - 查看继承记录列表

4. **校验工具**
   - 单活码员工校验（检查员工是否仍在企微、状态是否正常）
   - 全局员工校验（跨活码批量检查，识别不可用员工并替换）

5. **操作功能**
   - 暂停/恢复活码
   - 删除活码
   - 同步企微配置（重新生成二维码等）
   - 下载活码图片（PNG）

### 2.5 批量操作

**功能点：**

1. 批量修改欢迎语
2. 批量修改收集表单模板
3. 批量修改轮换模式
4. 批量分配到分组（教育联盟）
5. 批量修改预警阈值
6. 批量修改状态（暂停/恢复）
7. 批量修改场景
8. 批量下载活码图片（ZIP 打包）
9. 批量修改统一样式配置

## 3. 模块二：员工管理

### 3.1 模块概述

管理企微员工（接待员 / 服务老师），包括员工基本信息、每日接待上限、异常状态监控与恢复。

### 3.2 员工列表与筛选

**功能点：**

1. **员工列表页**
   - 分页展示所有员工（姓名、手机、部门、角色、日上限、已添加、状态）
   - 筛选：按角色（接待员 / 服务老师 / 双重）、按状态（正常 / 预警 / 已拦截 / 已熔断）
   - 关键词搜索

2. **员工通讯录同步**
   - 手动触发从企微 API 全量同步员工
   - 同步状态展示（在职 / 离职 / 禁用）
   - 存储企微侧状态（已激活 / 禁用 / 未激活 / 已离职）
   - `PatrolWorker` 每 5 分钟自动同步员工列表，更新部门信息
   - 自动拦截离职/禁用员工（wechat_status = 5），防止分配到活码

3. **员工恢复**
   - 将被拦截/熔断员工恢复为正常状态
   - 记录恢复操作日志

### 3.3 员工状态管理

**功能点：**

1. **四级状态体系**
   - `normal` — 正常接待
   - `warning` — 达预警阈值，减少分配权重
   - `blocked` — 达紧急阈值，停止分配（自动触发告警）
   - `melted` — 熔断（72小时内连续多次触发 → 临时移除）

2. **每日计数重置**
   - 凌晨 0:00 自动清零各员工当日添加数
   - Redis 实时计数器与数据库同步重置

3. **状态变更原因记录**
   - JSON 格式存储异常原因摘要

## 4. 模块三：全局员工池

### 4.1 模块概述

统一管理所有可分配员工的全局池，作为活码分配员工的第一来源。支持按部门、优先级、当日容量自动筛选。

### 4.2 功能点

1. **员工入池**
   - 员工创建时自动加入全局池
   - 设置全局日接待上限（`daily_max`）
   - 设置分配优先级（`sort_order`，越小越优先）
   - 关联企微部门 ID（从 employee 表同步取主部门）

2. **状态驱动分配**
   - `standby` — 可正常分配
   - `full` — 当日已达上限，暂停分配
   - `blocked` — 已拦截，不允许分配

3. **智能分配策略**
   - 优先同部门员工（活码 `department_id` 匹配池中员工 `department_id`）
   - 同部门内按 `sort_order` 升序
   - 同部门不足时从全池补足
   - 每日自动重置

4. **实时计数**
   - Redis 原子计数器跟踪每位员工当日已接待数
   - 达到上限后自动置为 `full` 状态

## 6. 模块五：在职继承

### 6.1 模块概述

「在职继承」是企业微信的核心功能：当客户添加接待员后，系统自动（或手动触发）将客户从接待员转移给服务老师，由服务老师进行长期维护和转化。

### 6.2 继承流程

```
1. 客户扫码添加接待员
2. 系统检测客户来源活码的继承配置
3. Infer 目标服务老师（按绑定目标配置 / 按角色匹配 / 按日上限负载均衡）
4. 调用企微「在职继承」API 发起转接
5. 企微推送回调通知继承结果
6. 继承成功：发送备注 + 问候语 + 转接通知
7. 继承失败：自动重试（指数退避）→ 超限 → 标记 api_failed
```

### 6.3 功能点

1. **继承触发**
   - 自动触发：客户添加后由 `CallbackWorker` 自动检测并触发
   - 手动触发：在活码详情页一键触发全部 / 选择性触发
   - 补录触发：将历史已添加但未继承的客户补录到继承表

2. **继承匹配**
   - 预览页面：查看待继承客户与目标老师的匹配关系
   - 服务老师匹配策略：
     - 按活码绑定的 `bind_target` 配置匹配
     - 按角色（`service` / `dual`）筛选
     - 按日上限负载均衡（选余量最大的）
     - 继承槽位保护（每个老师有独立的继承日上限 `service_daily_max`）

3. **继承执行与重试**
   - API 调用企微在职继承接口
   - 失败自动重试（最多 N 次，指数退避 30s → 1min → 2min …）
   - 达重试上限 → 状态标记 `retry_limit`
   - 区分 `retry_count`（API 失败重试）和 `poll_count`（待确认轮询）

4. **继承结果追踪**
   - 每 30 分钟轮询 `pending_confirm` 状态的继承记录
   - 追踪次数达上限 → 标记 `timeout`
   - 确认成功 → 标记 `confirmed`
   - 被拒绝 → 标记 `rejected`

5. **继承后处理**
   - **备注写入**：按模板自动为客户写入企微备注
     - 已填写客户：`{{grade}}{{class}} | 孩子：{{child_name}} | 来源：{{school_name}}`
     - 未填写客户：不写备注或写简化版
   - **问候语发送**：按模板自动发送问候消息
     - 已填写客户：`{{parent_name}}您好～我是{{school_name}}的专属服务老师{{teacher_name}}...`
     - 未填写客户：含表单链接引流的问候
   - **转接成功通知**：通知原接待员转接完成

6. **继承配置（活码级别）**
   - 启用/禁用继承问候语（NULL = 使用系统默认）
   - 自定义已填写备注模板
   - 自定义已填写问候语模板
   - 自定义未填写问候语模板
   - 自定义转接成功通知（支持空字符串 = 不发送）

7. **乐观锁并发控制**
   - `customer_transfer.version` 字段防止重复处理

8. **分时段调度策略（InheritanceJob）**
   - **日间模式**：每 15 分钟执行，处理最近 15-30 分钟内添加的客户
   - **夜间模式**：每天 8:30 一次性批量处理所有夜间新增客户
   - **dirty school 优化**：Redis Set `inheritance:dirty:schools` 追踪有新增客户的活码，无新增则跳过
   - **Redis 分布式锁**：`lock:inheritance:day-batch` / `lock:inheritance:night-batch` 防止多实例重复执行
   - **启动补偿**：应用启动时自动补偿过去 30 分钟内错过的继承窗口
   - **自动继承开关**：Redis 键 `inheritance:auto:enabled`，可通过接口实时开关

## 7. 模块六：欢迎语与收集表单

### 7.1 模块概述

收集表单是获取家长/学生信息的工具。客户扫码添加后，系统通过欢迎语推送表单链接，家长填写后自动打标签并写入企微备注。

### 7.2 表单模板管理

**功能点：**

1. **模板 CRUD**
   - 创建表单模板
   - 编辑表单模板
   - 删除表单模板（校验是否被活码引用）
   - 模板列表页

2. **表单字段定义**（JSON 配置）
   - 支持多种字段类型：单行文本、多行文本、单选、多选、下拉
   - 字段必填/选填设置
   - 字段排序

3. **表单页配置**
   - 自定义副标题（为空使用系统默认）
   - 自定义卡片标题
   - 自定义卡片描述
   - 自定义卡片图片链接

4. **标签映射规则**（JSON 配置）
   - 字段值 → 标签的映射关系
   - 自动打标签（提交后自动为客户打上对应标签）
   - 自动备注模板（`{{child_name}}-{{grade}}{{class}}`）

### 7.3 客户填表页面（C 端）

**功能点：**

1. **表单入口页**
   - URL：`/form/{qrCodeId}`
   - 显示表单标题、副标题
   - 区域联盟场景：显示学校选择下拉框
   - 表单字段渲染（根据模板 JSON 动态生成）
   - 表单校验（前端 + 后端双重校验）

2. **表单提交**
   - AJAX 异步提交
   - 提交成功 → 自动打标签 + 写入备注
   - 跳转成功页面

3. **提交成功页**
   - 显示成功提示
   - 展示全局联系人二维码（兜底客服）
   - 区域联盟场景：根据客户选择的学校展示对应的活码

### 7.4 欢迎语继承链

```
活码自定义欢迎语（qr_code.welcome_text）
  → 分组默认欢迎语（qr_code_group.default_welcome_text）
    → 学校分类默认欢迎语（school_category.default_welcome_text）
      → 系统默认欢迎语（system_config.default_welcome_text）
```

- NULL 或空字符串表示「继承上一级」
- 任意层级可覆盖（设置为非空值即生效）
- 支持模板变量：`{{school_name}}`

## 8. 模块七：异常告警中心

### 8.1 模块概述

多维度监控系统运行异常，自动触发告警、执行自动化动作，支持人工处理与批量解决。

### 8.2 告警类型

| 告警类型 | 说明 | 严重级别 | 自动动作 |
|---------|------|---------|---------|
| `blocked` | 员工达紧急阈值被拦截 | high | — |
| `melt` | 员工 24h 内多次熔断，临时移除 | high | melted |
| `greeting_fail` | 欢迎语发送失败 | medium | — |
| `low_approval` | 员工通过率过低 | medium | — |
| `high_delete` | 客户被删率过高 | medium | — |
| `traffic_spike` | 流量异常飙升 | medium | — |
| `empty_backup` | 活码无可用备选员工 | high | — |

### 8.3 功能点

1. **告警列表页**
   - 分页展示所有告警
   - 多维度筛选：按类型（7 种）、按严重级别（低/中/高）、按状态（未处理/已处理）、按员工、按活码
   - 时间范围筛选
   - 批量解决（勾选后一键标记为已处理）

2. **告警详情**
   - 告警基本信息（类型、级别、时间、关联员工/活码）
   - 异常详情（JSON 格式详情面板）
   - 自动动作记录（暂停/移除/熔断）
   - 处理记录（处理人、处理时间）

3. **告警处理**
   - 单条解决：填写处理人 → 标记为 `resolved`
   - 批量解决：勾选多条 → 一键标记
   - 支持筛选条件批量解决（如「解决所有 low_delete 告警」）

4. **巡检 Worker（PatrolWorker）**
   - 每 5 分钟执行员工状态巡检
     - 检查员工通过率 → 触发 `low_approval`
     - 检查客户删除率 → 触发 `high_delete`
     - 检查流量异常 → 触发 `traffic_spike`
     - 检查活码备选员工 → 触发 `empty_backup`
   - 每分钟执行熔断恢复检查
     - 检查已熔断员工是否冷却期满 → 自动恢复
   - 凌晨 3:07 生成日报快照

## 17. 模块十六：企业微信集成

### 17.1 模块概述

与企业微信 API 深度集成，实现 QR 码配置管理、客户回调接收、消息推送、员工通讯录同步、在职继承等能力。

### 17.2 功能点

1. **企微 API 客户端**（`WecomApiClient`）
   - Access Token 管理（自动获取、缓存、刷新）
   - 联系我（Contact Way）配置管理
   - 外部联系人管理（获取客户详情、获取客户列表）
   - 在职继承 API（发起转接、查询结果）
   - 消息推送（发送欢迎语、跟进消息）
   - 备注写入
   - 标签管理（获取标签列表、打标签、移除标签）
   - 通讯录同步（部门列表、员工列表、员工详情）
   - 异常分类处理（token 过期 / 限流 / 永久错误 / 瞬时错误）

2. **回调事件接收**（`WecomCallbackController`）
   - URL 验证（GET 请求 echostr 校验）
   - 事件推送（POST 请求 XML 解析）
   - 事件类型处理：
     - 添加外部联系人 → 触发客户创建 + 标签 + 继承
     - 删除外部联系人 → 更新客户状态
     - 在职继承结果通知 → 更新继承状态
   - **Fast Ack 模式**：快速返回 200 → 异步处理（Redis Stream）
   - 消息签名验证 + 解密

3. **企微 OAuth**（`WecomOAuthService`）
   - 构建 OAuth 授权 URL
   - 回调处理：code 换 userid
   - Session 管理

4. **消息防护**（`MessageGuardService`）
   - 消息去重（基于 Redis 的幂等性保证）
   - 频率控制
   - 回调签名验证

5. **自愈机制**（`WechatSyncHealingService`）
   - 检测数据不一致（如客户在企微侧已删除但 DB 未同步）
   - 自动补全缺失数据

6. **健康监控与死信队列（DLQ）**
   - **Stream 监控**：`GET /api/health/streams` 查询各 Redis Stream 队列长度、Pending 消息数、全局池 standby 数量
   - **死信队列（DLQ）**：消费失败的消息经 3 次重试后落入 `wecom:dlq:stream`
   - **DLQ 重放**：`POST /api/health/dlq/replay` 将 DLQ 消息手动重放到目标 Stream（callback / tag / datafill）
   - **消息去重**：`MessageGuardService` 基于 Redis 的幂等性保证，防止企微重复推送导致的重复处理
   - **回调快速确认**：企微回调接口采用 Fast Ack 模式（先返回 200，后异步处理），确保响应时间 < 20ms
