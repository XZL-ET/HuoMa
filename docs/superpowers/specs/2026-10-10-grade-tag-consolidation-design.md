# 年级标签归并 —— 设计（2026-10-10）

## 一、目标

把年级标签统一收敛到企微「年级」标签组，并让本地库账目与企微一致：

1. 客户身上的年级标签只出现在「年级」组；
2. 「学校-{市}」组不再持有任何年级标签；
3. 本地 `customer_tag` 的年级绑定指向「年级」组的本地 tag 行，`source` 不变；
4. 正向打标路径只进「年级」组（已由 2026-10-08 修复）。

## 二、现状（均为生产取证结论）

**企微侧基本是既成事实且大体正确。** 后台看到的 62,179 是真的，不是错误数：
它约等于全部"有年级信息的活跃客户"数。

抽样（生产 `externalcontact/get` 实查）：

| 抽样 | 样本 | 结果 |
|---|---|---|
| 待对账客户 | 300 | 191（64%）在企微已带「年级」组标签，0 个同时带旧组标签 |
| 按标签名比对 | 80 | 61 同名且在「年级」组 / 3 同名在他组 / 1 异名（升学改名）/ 15 企微里没有任何年级标签 |
| 归类 | 60 | 44 已带「年级」组 / 4 带的是「学校-{市}」组年级标签 / 12 企微里没有 |

解剖单个客户（124122）最能说明问题：本地 5 条绑定里，市州/县区/学校/班级 4 条的
`wecom_tag_id` 与企微**完全一致**，**只有年级那条对不上**——本地指向 `学校-天水市`
组的「一年级」(`...C4Ko2...`)，企微客户身上带的是「年级」组的「一年级」(`...74m0M...`)。

本地侧：约 6.15 万活跃客户的年级 `customer_tag` 绑定指向本地 tag 行，而这些行的
`wecom_tag_id` 有三种状态（本地 `学校`/`学校-{市}`/legacy 组的年级 tag 行共 172 行）：

| 类 | 本地行 `wecom_tag_id` | 客户企微实况 | 规模 |
|---|---|---|---|
| **R1** | ∈「年级」组标签 id | 已带「年级」组标签 | 约 76% |
| **R2** | ∈ 某「学校-{市}」组同名标签 id | 已带「年级」组标签（标记发生在漂移前）；少数（约 4%）带的是学校组标签 | 约 20% |
| **R3** | 企微里**已不存在**（legacy `group_keyword=''` 行，如 tag#125/126/127） | 企微里没有年级标签 | 约 1 万客户 |

## 三、根因

`TagService.getOrCreateTag()`（`TagService.java:325-338`）：本地 tag 行带
`wecom_tag_id` 时，会用缓存键 `实际组名|标签名` 反查企微，**一旦查出不同 id 就把本地行的
`wecom_tag_id` 改写掉**（本意是修 corp 切换/标签被删导致的僵尸 id）。

由于「学校-{市}」组里长出了与「年级」组**同名的重复年级标签**，这段逻辑就把本地账目
从「年级」组标签改指到「学校-{市}」组的同名标签。`customer_tag` 绑定行本身没动
（`source=form` 仍在），只是它指向的 tag 行 `wecom_tag_id` 指错了组。

正向路径已由 `docs/data-repair-20261008-grade-tag-group.sql` 把模板映射改为
`tag:年级` 堵住（模板提交时从库读，立即生效），**根因已不再产生新的学校组年级标签**。

**关键推论：不能按名字重接线，要按企微实际 tag id 重接线。** 因为每学期运营会手工把
企微年级标签名改一级（升学），本地名与企微名可能差一级，属正常（见 memory
`grade-tag-semester-promotion`）。例如本地行 211 名为`六年级`，其 `wid` 却是「年级」组的
`七年级`——按名重接线会指错。

## 四、范围

- **在**：12 个中小学年级名 —— 一年级…六年级 / 七年级…九年级 / 高一 / 高二 / 高三。
- **不在**（另开）：幼儿园（小班/中班/大班/幼儿园小班…）与「高中毕业」；班级（45,806 客户）。

## 五、方案

### Phase A —— 逐行分类 + 逐客户对账（后台 Job，可断点续跑）

**A0 行级分类（纯本地，无 API）**：遍历本地 172 个非「年级」组的年级 tag 行，按 `wecom_tag_id` 分类：

- **R1**：`wid` ∈ 企微「年级」组 id 集合 → 客户企微侧已对。**不做任何企微写**，只做本地重接线。
- **R2**：`wid` ∈ 某「学校-{市}」组 12 年级名标签 id → 需逐客户判定。
- **R3**：`wid` 在企微不存在 → 客户企微侧没有年级标签，需按本地名补打。

**A1 逐客户处理**：

- R1 行下的客户：**只做本地重接线**（见 A2），零企微调用。
- R2 行下的客户：读一次 `externalcontact/get`
  - 若已带「年级」组年级标签 → 取该 id 为目标，只做本地重接线；
  - 否则（带的是学校组标签或无）→ `markTag` 补打该行名对应的「年级」组标签（必要时先 `add_corp_tag` 创建），再做本地重接线。
- R3 行下的客户：`markTag` 补打本地行名对应的「年级」组标签，再做本地重接线。

**A2 本地重接线（按 wid，不按名）**：

1. 求出目标 `wid`（R1 行 = 该行 `wid`；R2/R3 = 判定/补打的「年级」组标签 id）。
2. 找 canonical 本地行 = `tag` 表里 `wecom_tag_id = 目标 wid` 且 `group_keyword='年级'` 的行
   （12 个名字各有一条，如 tag#1184=一年级、#1190=七年级）。若不存在则新建
   `(name=<企微该标签当前名>, group_keyword='年级')`。
3. 把客户的年级 `customer_tag.tag_id` 改成 canonical 行 id；`source` 保持原值（保
   `TransferService.checkFormFilled` 语义不变）。
4. 撞 `(customer_id,tag_id)` 唯一键时，删除多余的那条重复行。

**幂等性**：R2/R3 的 `markTag` 是 add（幂等，重复 add 已存在的标签无副作用）；A2 重接线
若已是 canonical 行则空操作。因此**重跑 = 续跑**，不需要额外的"已处理"标记来保证正确性；
进度表仅用于观测与断点续跑省时。

**限流**：沿用现有 600/min 模式（每 100 次调用 sleep 10s）。R2 最多约 1.5 万次读 + 少量
写；R3 约 1 万次写。总计约 25–40 分钟。

### Phase B —— 删企微「学校-{市}」组里的年级重复标签

- **白名单**：实时拉 `get_corp_tag_list`，取组名 ∈ {`学校`, `学校-{市}`…}（即非
  `年级`/`班级`/`市州`/`县区`/`渠道来源` 的组）且标签名**精确等于** 12 个年级名之一的标签 id。
- **前置**：Phase A 必须已完成（R2/R3 客户先把「年级」组标签打上，否则删掉旧标签后他们就没年级标签了）。
- **执行**：`del_corp_tag`（corp 级删除，企微会自动从所有客户身上摘掉）。
- **安全**：必须**精确名字匹配**，绝不能用 `LIKE '%班%'`——`学校-*` 组里有 `中班`/`小班`
  和学校名`舟曲县憨班镇中心小学`（landmine）。幼儿园相关名不在 12 名白名单内，天然排除。

### Phase C —— 清理本地孤儿 tag 行

- 删除重接线后不再被任何 `customer_tag` 引用的非「年级」组年级 tag 行（R1 行也应删除，
  因为它与 canonical 行重复）。
- **顺序要求**：必须先确认无 `customer_tag` 引用再删 tag 行。否则 `getOrCreateTag` 的
  僵尸 id 修复若再被调用，会因企微标签已删而重同步、甚至重建学校组标签，抵消 Phase B。

### Phase D —— 校验

- 抽 300 客户：企微年级标签 100% 在「年级」组。
- 企微「学校-*」组里无 12 年级名标签。
- 本地：无 `customer_tag` 指向非 canonical 年级 tag 行。
- 正向回归：新提交一份表单，验证年级打「年级」组。

## 七、风险与缓解

| 风险 | 缓解 |
|---|---|
| 升学改名导致按名补打错一级 | R1 零风险（按 wid）；R2 先读企微按 id；R3 无企微标签，只能按本地名，**输出报告供人工复核** |
| `del_corp_tag` 行为未验证（官方文档 WebFetch 被挡） | 上线前 preflight：先 dry-run 比对白名单，再删 1 个标签实测 |
| `mark_tag` 幂等性未从官方文档确认 | 上线前 1 客户 smoke test |
| 双节点 active-active | 迁移 Job 加分布式锁（复用 `ScheduledJobGuard`） |
| 限流 45035/600·min | 沿用 sleep 10s/100 |
| 误删学校名/幼儿园标签 | 白名单精确名字匹配；dry-run 先出清单人工过目 |
| 破坏 `checkFormFilled` | 重接线保留 `source` |

## 八、验收标准

1. 企微「学校-*」组中 12 个年级名标签数为 0；
2. 抽样 300 客户企微年级标签全在「年级」组；
3. 本地无 `customer_tag` 指向非 canonical 年级 tag 行；
4. 新表单提交年级打「年级」组；
5. Phase A 报告里"按本地名补打"的客户清单已人工复核。

## 九、已确认决策（2026-10-10）

1. **R3（约 1 万，企微无年级标签）**：按本地名补打进「年级」组，并输出客户清单供人工复核。
2. **R2 采用逐客户读企微**（`externalcontact/get`，约 1.5 万次调用、~25 分钟），按企微实际
   tag id 精对接线；放弃"盲打 + 按行名"的省调用方案。
3. **范围**：幼儿园（小班/中班/大班/幼儿园小班…）与「高中毕业」本次不动，另开任务。
