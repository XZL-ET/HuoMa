## 1. 需求概述

### 1.1 背景

当前活码管理存在两种组织方式：

| 类型 | 结构 | 服务老师 |
|---|---|---|
| **一校一码** | 每个学校一张活码（`QrCode`，绑定 `school_id`） | 学校级专属老师 |
| **学区码（联盟）** | 一个学区一张活码（`QrCodeGroup` alliance），`school_list` 手动维护学校名 | 学区级共享老师 |

现需新增 **县区码**：家长扫码添加县区接待员后，弹出收集表单，选择【学校（县区下所有学校）→ 年级 → 班级】，打相应标签，再**在职继承转接到对应学校的服务老师名下**。

核心痛点：单县区上百所学校，家长在长列表里翻找成本高。

### 1.2 县区码 与 学区码 的区别（关键）

| | 县区码 | 学区码 |
|---|---|---|
| 活码类型 | 企微联系我活码（新增） | 联盟活码（已有） |
| 绑定员工 | 县区级接待员 | 学区级共享老师 |
| 学校列表来源 | 县区下所有学校（自动查 `School` 表） | 学区内学校名（`school_list`） |
| 选学校的结果 | 打标签 + **在职继承转接到学校服务老师** | 打标签（归属学区老师，不转接） |

### 1.3 核心目标（已与需求方确认）

- 县区码 = 企微联系我活码，绑定县区接待员
- 扫码 → 加接待员 → 弹收集表单 → 选【学校→年级→班级】→ 打标签 → 在职继承转接
- 学区码：选学校只打标签，不转接（学区老师就是学校老师）
- **降低选择成本**：学段收窄 + 搜索（拼音首字母/中文模糊）+ 记住上次选择

### 1.4 关键决策记录

| 决策点 | 结论 |
|---|---|
| 县区码形态 | 企微联系我活码（scene=2），扫码即加县区接待员 |
| 学校列表来源 | 按 `region_district` 自动查 `School` 表（不再靠手动 `school_list`） |
| 选学校结果 | 打标签 + 在职继承转接到对应学校服务老师 |
| 学区码选学校结果 | 只打标签，不转接 |
| 学段筛选 | 第一步先选学段 |
| 年级班级 | 年级按学段固定枚举，班级手填，打标签（`tag_mapping` 配置 grade/class → tag） |
| 记忆深度 | 第一版 localStorage |

## 2. 交互设计

### 2.1 县区码完整流程

```
家长扫「县区码」（企微联系我活码，state=县区标识）
   → 直接加县区接待员           ← 扫码即加，只有这一步
   → 系统发欢迎语 + 收集表单卡片
   → 家长填表单：
      ① 选学段（小学/初中/高中/幼儿园）
      ② 选学校（搜索 + 列表，县区下所有学校）
      ③ 选年级（按学段枚举）+ 填班级
   → 提交
   → 系统打学校标签 + 年级班级标签
   → 在职继承：转接到该学校对应的服务老师名下
```

### 2.2 表单页三级选择（改造现有 `form/fill.html`）

```
┌─────────────────────────────┐
│       请选择孩子的学校        │
├─────────────────────────────┤
│ ① 学段（大按钮）             │
│    [小学] [初中] [高中] [幼儿园]│
├─────────────────────────────┤
│ ② 学校（搜索 + 列表）         │
│    🔍 搜索学校名称 / 拼音     │
│     XX小学        XX初中      │
├─────────────────────────────┤
│ ③ 年级 + 班级               │
│    年级 [三 ▼] 班级 [2班]     │
└─────────────────────────────┘
   [上次：XX小学 三(2)班，确认？]  ← 有 localStorage 时置顶
```

### 2.3 选择成本降低三手段

1. **学段收窄（第一优先）**：用 `School.category_id`，把上百所筛到二三十所。
2. **搜索框**：拼音首字母 + 中文模糊，前端本地过滤（列表已加载）。
3. **记住上次选择**：`localStorage` 存 `{schoolName, grade, className}`，二次扫码一键回填。

### 2.4 学段 → 年级枚举映射

| 学段 | 年级枚举 |
|---|---|
| 小学 | 一年级 ~ 六年级 |
| 初中 | 初一 ~ 初三 |
| 高中 | 高一 ~ 高三 |
| 幼儿园 | 小班 / 中班 / 大班 |

班级为自由文本。

## 3. 在职继承转接（核心新增逻辑）

### 3.1 触发点

从「扫码回调时」改为「**表单提交后**」。因为县区码扫码回调的 `state` 是县区标识、不是学校，学校信息要等家长填表单才知道。

### 3.2 目标服务老师的解析

家长填表单选了 `school_name`，系统需要解析出「该学校对应的服务老师」。解析链：

```
school_name
   → ① 查 School 表得到 school_id
   → ② 查 QrCode.findBySchoolId(school_id)
        ├─ 找到学校自己的活码 → 取该活码的 service 老师（一校一码场景）
        └─ 找不到 → 该学校包在学区码里
             → ③ 查 QrCodeGroup（school_list 含该校名）→ 取学区码活码的 service 老师
```

- **一校一码的学校**：目标 = 学校自己活码的 `QrAgent`（role=service）
- **包在学区码的学校**：目标 = 学区码活码的 `QrAgent`（role=service），学区老师即学校老师

### 3.3 复用现有 TransferService

`TransferService.initiate(customerId, fromUserid, toUserid, externalUserid, state)` 已支持：
- 显式传 `toUserid`（3.2 解析出的目标老师）
- 内部按 `state` 查活码、找 service 老师、调 `transfer_customer`

接线点：`FormController.submit()` 保存 `FormSubmission` 后，调用 `TransferService.initiate()`，`fromUserid` = 县区接待员（客户的 `currentAgent`），`toUserid` = 3.2 解析出的学校服务老师。

### 3.4 归属异步的代价（如实告知）

- 在职继承有 24h 确认窗口，归属不是扫码瞬间，而是继承完成后
- 热门学校老师可能触及 `errcode 84097`「接替成员客户数已达上限」，走失败重试/告警（现有机制已覆盖）

## 4. 数据设计

### 4.1 学校列表来源

- 县区码：按 `region_district` 查 `School` 表（`deleted=false`），按 `category_id` 学段筛选
- 学区码：`school_list`（保留，作为学区码的学校名来源）

### 4.2 新增接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/form/schools?qrCodeId=1&category=小学` | 返回县区下、指定学段的学校列表（JSON） |
| GET | `/api/form/grades?category=小学` | 返回学段对应的年级枚举（JSON） |

后端根据 `qrCodeId` → `QrCode.groupId`（或县区码标识）→ 县区 → 查 `School` 表。

### 4.3 表单提交扩展

`FormSubmission.field_data` JSON 增加结构化字段：

```json
{
  "school_name": "XX小学",
  "grade": "三年级",
  "class": "2班",
  "child_name": "张三"
}
```

- `school_name` 已有，保留
- 年级班级打企微标签（复用现有 `TagService.applyFormTags` 的 `tag_mapping` 机制，表单模板配置 `{"grade":"tag","class":"tag"}` 即自动打标签，无需新增代码）

## 5. 标签与备注

- **学校标签**：`TagService` 三级地理标签（城市/区县/学校）已覆盖，无需改动
- **年级班级标签**：`TagService.applyFormTags` 已支持按 `tag_mapping` 打标签（`"tag"` / `"tag:组名"`），表单模板配置 `{"grade":"tag","class":"tag"}` 即自动打年级/班级企微标签，无需新增代码
- **备注**：`remark_template` 仍可按需拼接（如 `{{child_name}}`），与打标签互不影响

## 6. 技术实现

### 6.1 修改文件

| 文件 | 修改内容 |
|---|---|
| `FormController.java` | 新增 `/api/form/schools`、`/api/form/grades`；`submit()` 后触发在职继承 |
| `templates/form/fill.html` | 学校选择升级为三级级联（学段+搜索+学校+年级班级）+ localStorage 记忆 |
| `SchoolRepository.java` | 新增按 `regionDistrict + categoryId + deleted=false` 查询方法 |
| `TransferService.java` 或新增 service | 学校 → 服务老师解析链（一校一码 / 学区码兜底） |
| `QrCodeService.java` 或 `QrCodeGroupService` | 提供「县区码 → 学校列表」「学校 → 学区码」查询 |

> **年级/班级打标签无需改代码**：`TagService.applyFormTags` 已通过 `FormTemplate.tag_mapping` 支持 `"tag"` / `"tag:组名"`，只需在县区码所用表单模板里配置 `{"grade":"tag","class":"tag"}`（数据配置，非代码改动）。

### 6.2 不改的部分

- 企微活码创建/回调（`WecomApiClient` / `WecomCallbackController`）
- 打标链路（`TagService` / `TagWorker`）
- 在职继承核心（`TransferService.initiate/trackResults`），只加接线

## 7. 边界与风险

| 风险 | 应对 |
|---|---|
| 学校 `category_id` 为空 | 学段筛选加「未分类」兜底桶，搜索仍可命中 |
| 学校名在 `school_list` 与 `School` 表不一致 | 解析链找不到时记录日志，兜底到县区接待员不转接 |
| 学校既无独立活码、也不在学区码里 | 不转接，留在县区接待员，日志告警 |
| localStorage 跨设备失效 | 仅作便利，后续升级微信 OAuth |
| 在职继承失败/超时 | 现有 `TransferService` 重试/告警机制已覆盖 |
