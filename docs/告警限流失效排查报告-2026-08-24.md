## 四、限流失效根因（`qr_agent_anomaly`）

### 现象

`PatrolWorker.patrolQrAgentAnomalies()` 设计「每小时最多告警一次」，但近 7 天按小时统计**稳定每小时 2 条**（偶有 1 条），且两条间隔 5~15 分钟、对与对之间约 50 分钟。

### 铁证（全部实测）

| 验证项 | 结果 | 方法 |
|---|---|---|
| 单例 | `PatrolWorker` 原始对象仅 1 个 | `jmap -histo:live` |
| 单调度线程 | 仅 `scheduling-1` | `jstack` |
| 限流值 1 小时 | `3600000l` | `javap -c` 反编译 |
| 唯一产生点 | 全 JAR 仅 `PatrolWorker` 一处 | 解包 `grep -rl` |

### 根因

`jmap` 显示 `PatrolWorker` 实际存在 **3 个对象**：

```
com.bookstore.qrcode.worker.PatrolWorker                  1 个（原始对象）
com.bookstore.qrcode.worker.PatrolWorker$$SpringCGLIB$$0  1 个（AOP 代理）
com.bookstore.qrcode.worker.PatrolWorker$$SpringCGLIB$$1  1 个（@Lazy self 代理）
```

CGLIB 代理通过**继承**创建子类，而 `lastAnomalyAlertTime` 是普通实例字段（非 `static`），因此每个代理实例都持有独立的字段副本。当 `patrol()` 经调度器持有的代理执行、`self.patrolQrAgentAnomalies()` 经 `@Lazy self` 代理执行时，限流状态被写入不同的字段副本，形成两个独立的 1 小时周期，叠加出「每小时 2 条」。

## 六、已实施的修复

将 3 个类共 5 个限流字段从「实例字段」改为「`static volatile`」，从根本消除 CGLIB 代理字段分裂：

| 文件 | 字段 | 限流用途 |
|---|---|---|
| `PatrolWorker.java` | `lastAnomalyAlertTime` | 异常巡检告警（1h） |
| | `lastDlqReplayTime` | DLQ 自动重放（30min） |
| `TransferMonitorWorker.java` | `lastDlqAlertTime` | DLQ 积压告警（1h） |
| | `skippedDlqAlertCount` | DLQ 告警跳过计数 |
| | `lastStreamBacklogAlertTime` | Stream 积压告警（1h） |
| `InheritanceJob.java` | `lastNoServiceAlertTime` | 缺服务老师告警（1h） |

`static` 使字段属于类而非实例，所有 CGLIB 代理子类共享同一状态；`volatile` 提供多线程可见性保证（防御性）。编译验证通过（`mvnw compile` exit 0）。

> 注：单实例部署下 `static` 已足够；若未来多实例部署，此类「内存级限流」需升级为 Redis 分布式限流（`TransferMonitorWorker` 已用 Redis 锁防并发，可参照扩展）。
