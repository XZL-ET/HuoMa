## 1. 背景与目标

### 1.1 为什么要做（业务价值）

火马是书店面向家长的家校服务平台，核心价值是给家长推送与「孩子所在年级/科目」匹配的精准内容——试题、学习资料、活动通知等。要做到精准，系统必须知道「这个家长的孩子在哪个年级、学哪些科目」。

**年级/科目标签，就是精准服务的「钥匙」：** 有了它，才能按年级、按科目把对的资料发给对的家长；没有它，只能发不区分年级的通用内容，服务的价值大打折扣。

### 1.2 现状与痛点（量化）

- 全量客户约 **11 万**，其中**只有约三成（~3.3 万）有年级/科目标签，约 7.7 万（~70%）缺失**。
- 缺标签的直接原因：年级/科目只能靠欢迎语表单收集，而表单随 `send_welcome_msg` 的 `welcome_code` 只能发一次、约 20 秒有效、一次性。家长在添加好友那一刻没填，之后就再也没有合规的通道能把表单补发给他。
- 由此造成的损失：
  1. 这 7.7 万家长**收不到按年级/科目的精准内容**，体验打折；
  2. 书店按年级的精准运营**覆盖率只有约 30%**，7 成客户的价值没有充分挖掘；
  3. 而且这个缺口在**持续累积**——新客户只要在添加时没填表，就会不断掉进「缺标签」的池子，越积越多。

### 1.3 为什么现在能做

卡点的本质不是「发不出去」，而是「填了之后认不出是谁」。现在有了解决这个身份问题的钥匙：

- 企业有**同主体的公众号**，可以用来做微信身份识别；
- 通过「`convert_to_openid` 批量建 external_userid↔openid 映射 + 表单走公众号网页授权拿 openid + 反查」，就能把「谁填了表单」对应回具体客户，实现**静默自动打标签**；
- 再叠加「填表送试题」的钩子，家长愿意填，填写率有保障。

一句话：以前是「发得出去但认不出人」，现在「认得出人」了，整条链路才第一次闭环。

### 1.4 目标

1. **触达**：把这批未打标签家长再触达一次，让其补填年级 + 科目。
2. **打标**：填写后**静默自动打标签**（年级 + 科目），无需人工。
3. **填写率**：用「填表送本年级、本科目试题」的钩子降低家长排斥、提升填写意愿。
4. **附加价值**：试题跳转带动公众号访问量与自愿关注。

### 1.5 非目标（本期不做）

- 不强制关注公众号（规避诱导关注合规风险）。
- 不做试题内容的自动生成/排版（由公众号运营侧人工准备）。
- 不做群发后的自动化重试/漏发补发（留待扩展阶段）。
- 不改动既有欢迎语表单业务（补发表单为独立新表单，复用模板体系）。

## 2. 角色定义

| 角色 | 说明 |
|------|------|
| 管理员 | 在火马后台操作「补发表单」的人，负责筛选范围、发起群发、催办、查看进度 |
| 员工 | 企业微信成员，名下有客户，负责在企微端确认群发任务 |
| 家长 | 微信用户，客户的直接操作者，填写表单、领取试题 |

## 3. 核心业务流程

### 3.1 员工侧（发送）

1. 管理员在后台勾选补发范围（按学校/员工），看到「将触达 N 名未打标签家长」，点「发起群发」。
2. 系统按员工分批，为每个员工创建一个群发任务（`sender`=该员工、`external_userid`=其名下未打标签家长），文案 + 表单链接卡片。
3. 员工在企业微信 App 收到「群发待确认」提醒（工作台 → 客户联系 → 群发助手）。
4. 员工点进去，预览内容与客户数，点「发送」确认。
5. 企微将消息发到这些家长的微信，员工看到发送完成回执。

### 3.2 家长侧（领取试题）

1. 家长在微信收到消息（文案 + 链接卡片）。
2. 点链接 → 打开表单页（期间不到 1 秒静默授权，家长无感）。
3. 看到表单：学校已预填，选年级（单选）、勾选科目（多选），点「提交」。
4. 提交成功 → 系统静默打标签（年级 + 每个所选科目）。
5. 页面在表单页内展示一组试题链接（每个所选科目一条），家长逐条点开。
6. 家长在图文里看试题（图片），顶部有公众号关注按钮，自愿关注。

## 4. 功能需求

### 后台管理

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-01 | 筛选未打标签家长 | 按学校/员工筛选，条件：`currentAgent` 非空、`sourceQrId` 非空、无 `source=form` 的 `CustomerTag`；实时预览数量 |
| FR-02 | 发起群发 | 按员工分批，每批 ≤ 1 万 external_userid；调 `add_msg_template`，文案「填写年级和科目，免费领本年级试题」+ 表单链接卡片 |
| FR-03 | 催办提醒 | 发起后给相关员工发内部应用消息（`sendAppMessage`）：「你有一批群发待确认，请到群发助手点发送」 |
| FR-04 | 进度查看 | 展示每个群发任务的覆盖人数、确认/发送状态、已完成/未确认名单 |
| FR-05 | 年级×科目→试题链接映射管理 | 维护 `paper_link`：年级 + 科目 → 试题图文永久链接、标题；支持增删改查 |

### 表单与打标签

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-06 | 表单文案包装 | 副标题「填写年级和科目，免费领本年级试题」；字段为「年级（单选）+ 科目（多选）」 |
| FR-07 | 静默身份识别 | 无 `c` 参数时走公众号网页授权（`snsapi_base`），openid 反查 external_userid → customerId + sourceQrId（延后接入） |
| FR-08 | 年级/科目提交 | 表单字段含年级（单选）、科目（多选），学校预填 |
| FR-09 | 静默打标签 | 提交后走现有 `applyFormTags` / `markTag` 链路，年级打「年级」标签、科目打「科目」组标签，家长无感 |
| FR-10 | 提交后返回试题链接 | 按所选「年级 × 科目」查映射返回**一组**链接（每科目一条），前端在表单页内展示 |
| FR-11 | 未命中兜底 | openid 反查未命中时，回退「自报昵称 + 待人工核对」 |

### 数据与任务

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-12 | 批量建 openid 映射 | 后台任务对未打标签家长逐个 `convert_to_openid`，落 `customer_openid_map`；限速、幂等、断点续跑 |

## 5. 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NFR-01 | 限速 | `convert_to_openid` 批量建映射、群发调用均需限速，避免触发企微频率限制（如 45009/41048） |
| NFR-02 | 幂等 | 映射表按 external_userid 唯一；群发任务不重复创建（同一家长不重复收） |
| NFR-03 | 断点续跑 | 批量建映射失败可从中断处恢复，不重复、不遗漏 |
| NFR-04 | 合规 | 仅用 `snsapi_base` 静默授权；不强制关注；不诱导分享 |
| NFR-05 | 安全 | openid 映射表为敏感身份数据，仅内部使用，不对外暴露、不落日志明文 |

## 7. 验收标准

1. 后台发起群发后，相关员工能在企微端收到待确认任务，确认后家长在微信收到消息。
2. 家长点链接 → 选年级 + 勾科目 → 提交后，该家长在企微侧出现对应年级标签与所选科目标签。
3. 提交后页面展示一组试题链接（每个所选科目一条），可逐条点开。
4. openid 反查命中率经 spike 验证可用（详见设计文档第 7 节）。
5. 未命中反查的家长能走「自报昵称 + 人工核对」兜底，不丢失。

## 9. 风险与边界

- 群发需员工确认，存在「员工不点确认」导致触达率下降 → 靠 FR-03 催办 + FR-04 进度跟进兜底。
- 试题图文永久链接依赖公众号推文存续，推文删除则链接失效 → 需重新维护映射（FR-05）。
- `convert_to_openid` 仅支持 `wm` 微信外部联系人，不支持 `wo` 企业微信联系人（家校场景家长均为微信用户，符合）。
- 表单网页授权测试需真微信点击，单测仅能 mock，进度受真机验证影响。
