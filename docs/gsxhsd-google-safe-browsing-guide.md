## 1. 问题确认

### 1.1 Google Safe Browsing 透明报告

在浏览器打开以下链接，查看 Google 对 `gsxhsd.com` 的当前判定：

```
https://transparencyreport.google.com/safe-browsing/search?url=gsxhsd.com
```

- 如果显示"此网站可能包含有害内容"，确认被标记。
- 如果显示"未发现有害内容"，说明标记已解除或已过期。

### 1.2 Google Search Console（最重要的一步）

需要 `gsxhsd.com` 域名的控制权验证。如果你尚未添加，现在就添加：

**添加并验证域名：**
1. 登录 [Google Search Console](https://searchconsole.google.com/)
2. 点击「添加属性」→ 选择「网域」类型，输入 `gsxhsd.com`
3. 按提示完成 DNS 验证（在万网/阿里云 DNS 控制台添加一条 TXT 记录）
4. 验证成功后，进入左侧菜单「安全问题」

**在「安全问题」页面你将看到：**
- 具体被标记的页面 URL / 路径
- 恶意内容类型（社交工程/钓鱼/恶意软件/垃圾内容）
- 检测到问题的日期

> ⚠️ **这是最关键的信息来源。** 申诉之前必须搞清楚哪些页面被标记、因为什么被标记。

### 1.3 确认子域名影响范围

在 Chrome 中分别访问以下地址，确认是否都被拦截：

| URL | 是否被拦截 |
|-----|-----------|
| `https://www.gsxhsd.com/` | 主站 |
| `https://huoma.gsxhsd.com/` | 活码平台 |
| `https://gsxhsd.com/` | 裸域名 |
| 其他子域名... | |

Google Safe Browsing 的标记通常覆盖整个域名，所以所有子域名都会被连带影响。

## 2. 定位问题

### 2.1 确认被标记的具体页面

Google Safe Browsing 标记通常会指向具体触发的 URL。首先确认是哪个页面触发了标记：

**通过 Google Search Console 查看（推荐）：**
1. 登录 [Google Search Console](https://searchconsole.google.com/)
2. 选择 `gsxhsd.com` 属性
3. 左侧菜单 →「安全问题」→ 查看被标记的具体 URL

### 2.2 从用户视角审查表单页面

> **本次实际原因：** `huoma.gsxhsd.com/form` 页面原本缺少品牌标识，用户打开后看到的是无归属的信息采集页，被误认为是钓鱼页面而举报。

逐项检查以下常见问题：

- [ ] 页面是否有明确的**机构名称和 Logo**（甘肃省新华书店）？
- [ ] 用户能否一眼看出**谁在收集信息**？
- [ ] 表单是否说明了**收集信息的目的**（教材配送）？
- [ ] 是否说明了**信息不会被用于其他用途**？
- [ ] 页面底部是否有**客服电话、官方网址等联系方式**？
- [ ] 页面是否通过 **HTTPS** 提供服务？
- [ ] 表单收集的信息是否必要且合理？（只收集年级/班级，不收集姓名/身份证/手机号）

### 2.3 检查其他可能被误判的页面

| 检查项 | 说明 |
|--------|------|
| 品牌标识 | 所有对外页面都应包含新华书店 Logo + 名称 |
| 表单用途说明 | 清楚说明收集什么信息、为什么收集、如何使用 |
| 隐私声明 | 承诺不将信息用于收集目的之外的场景 |
| 联系方式 | 页脚含客服电话、地址、官网链接 |
| HTTPS | 所有含表单的页面必须通过 HTTPS 提供服务 |

### 2.4 快速安全自查（排除服务器被入侵）

虽然本次大概率是误报，仍建议做一次快速检查：

```bash
# 在 ECS 服务器上执行：检查最近被修改的文件
find /opt/HuoMa -type f -mtime -30 -ls

# 检查 nginx 配置是否被篡改
cat /etc/nginx/conf.d/huoma.conf

# 检查是否有异常进程
ps aux | grep -v grep | grep -E "huoma|java|nginx"
```

- ✅ 确认全站 HTTPS 配置正常

### 3.2 如果不是误报——清理恶意内容的流程

如果你的排查结果发现网站确实被入侵，参考以下流程：

1. **先备份留取证据**：`cp -r /var/www/html /tmp/html-backup-$(date +%Y%m%d)`
2. 删除注入的恶意 `<script>` / `<iframe>` 标签
3. 清理被上传的恶意文件（webshell、钓鱼页面等）
4. 清理所有垃圾评论、含外链的用户生成内容
5. 如果网站使用 CMS，将核心文件和插件更新到最新版本
6. 修复入侵入口：更换所有密码、启用 SSH 密钥登录、部署 WAF

## 4. 提交申诉

### 4.1 问题原因

经排查，此次被标记并非网站遭受恶意攻击。实际原因如下：

**被标记的页面：** `huoma.gsxhsd.com/form`（学生信息收集表单）

**问题根源：**
- 该表单是甘肃省新华书店「活码平台」的学生年级/班级信息收集页面，用于教材教辅配送服务；
- 表单原本**缺少甘肃省新华书店的品牌标识**（Logo、机构名称、联系方式等），用户打开后看到的是一个无品牌归属的信息采集页；
- 部分用户认为该页面是仿冒的钓鱼页面，通过 Chrome 的"报告不安全网站"功能进行了举报；
- 举报量累积后触发了 Google Safe Browsing 的自动标记机制，导致整个 `gsxhsd.com` 域名被标记。

**表单实际收集的信息（仅用于教材配送服务）：**
- 学生所在**年级**和**班级**（用于教材分班配送）
- **不收集**学生姓名、身份证号、手机号、家庭住址等个人身份信息
- 表单提交后仅用于生成班级教材发放清单，不用于任何营销或商业用途

### 4.2 已完成的整改

- ✅ 在表单下方添加了 **隐私声明**，明确说明：
  - 信息收集方为甘肃省新华书店
  - 仅收集年级、班级两项信息，不涉及个人身份信息
  - 所收集信息仅用于学生教材配送服务，不会用于其他任何场景

### 4.3 建议补充的整改（推荐在申诉前完成）

为了让 Google 审核人员和用户一眼确认这是正规机构页面，建议补充：

- [ ] 在页面底部添加**页脚**，包含客服电话、官方网址 `www.gsxhsd.com`
- [ ] 确认页面通过 HTTPS 提供服务，地址栏显示安全锁图标

> 品牌标识的缺失是这次被误报的根本原因。隐私声明解决了"文字说明"的问题，但 Logo 和页脚能解决"视觉信任"的问题 — 用户不需要阅读就能知道这是谁的表单。

**Nginx 安全头配置：**
```nginx
# 在 nginx.conf 的 server 块中收紧 CSP 策略
add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net https://unpkg.com https://cdn.bootcdn.net; style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net https://cdn.bootcdn.net; img-src 'self' data:; frame-ancestors 'none'; base-uri 'self'; form-action 'self';" always;
```

- 上传文件使用白名单校验（MIME 类型 + 文件头魔数）

- 每个对外表单页面必须包含品牌标识 + 隐私声明组件

## 附录：常见恶意内容类型

### A. 社交工程 / 钓鱼（你当前遇到的情况）

**特征：**
- 页面伪装成银行/支付/邮箱登录页
- 假冒"中奖信息""系统升级""账号异常"弹窗
- 要求输入用户名、密码、身份证号、银行卡号
- 仿冒知名品牌（淘宝、京东、银行、运营商等）的页面

**常见注入方式：**
- 被入侵的 CMS 安装目录下的 webshell
- 第三方统计代码/客服代码被篡改
- 攻击者直接替换了首页文件

### B. 恶意软件下载

**特征：**
- 自动触发 `.exe`、`.apk`、`.dmg`、`.scr` 文件下载
- 提示"您的 Flash Player 需要更新"
- 提示"您的手机已感染病毒，请安装防护软件"

### C. SEO 垃圾内容

**特征：**
- 页面中隐藏大量关键词和链接（用户不可见，搜索引擎可见）
- 被注入了药品、赌博、色情相关的链接

### D. 加密货币挖矿脚本

**特征：**
- 页面包含 `CoinHive`、`coinhive` 等 JS 挖矿脚本
- 访问时 CPU 持续 100%
