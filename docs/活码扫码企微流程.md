# 活码扫码后请求企微的完整流程

> 生成日期：2026-06-12

---

## 概述

家长扫描学校的"联系我"活码 → 添加书店企微员工为好友 → 企微服务器回调通知 → 系统异步处理（客户入库、打标、日限轮换、在职继承）。

核心架构：**Fast Ack + Redis Stream 异步消费**，回调接口在 20ms 内返回，所有业务逻辑异步完成。

---

## 阶段一：家长扫码加好友

```
家长微信扫活码 → 添加书店企微员工为好友 → 企微服务器接受好友请求
```

活码由 `QrCodeService` 通过 `POST /externalcontact/add_contact_way` 创建，每个学校一张活码，绑定若干接待员工。

---

## 阶段二：企微回调 → Fast Ack

企微服务器向 **`POST /api/wecom/callback`** 发送加密 XML，由 `WecomCallbackController` 处理：

```text
① 读取 HTTP Body（加密 XML）
② SHA-1 验签 + AES-256-CBC 解密（WecomCallbackValidator）
③ 提取关键字段：
   - Event: change_external_contact
   - ChangeType: add_external_contact
   - ExternalUserID: wmxxx（客户外部 ID）
   - UserID: zhangsan（添加的企微员工 ID）
   - State: school_123（活码创建时写入的透传参数，包含学校 ID）
④ 构建标准化 JSON 事件
⑤ XADD 写入 Redis Stream: wecom:callback:stream
⑥ 立即返回 HTTP 200 "success"
```

**不查数据库、不调企微 API**，纯异步入队，响应时间 <20ms。

## 阶段三：CallbackWorker 异步消费（核心业务）

`CallbackWorker` 单线程从 Redis Stream (`wecom:callback:stream`) 消费，按 `event_type` 路由：

| event_type | ChangeType | 处理方法 |
|---|---|---|
| `change_external_contact` | `add_external_contact` | `handleAddSuccess()` |
| `change_external_contact` | `del_external_contact` | `CustomerService.handleDelete()` |
| `change_external_contact` | `add_fail` | `AlertService.handleAddFail()` |
| `change_external_contact` | `greeting_fail` | `AlertService.handleGreetingFail()` |
| `add_external_contact` | — | `handleAddSuccess()` |
| `del_external_contact` | — | `CustomerService.handleDelete()` |
| `add_fail` | — | `AlertService.handleAddFail()` |
| `greeting_fail` | — | `AlertService.handleGreetingFail()` |

### handleAddSuccess() 五步处理

每一步都有独立的 try-catch，一步失败不影响其他步骤：

---

#### 步骤 1：频控检查

**服务**：`RateLimiterService.recordAdd(userId)`

**Redis 滑动窗口**：

| 窗口 | 阈值 | 动作 |
|------|------|------|
| 15 秒内 | >20 次 | 告警（日志 + 100ms 延迟） |
| 60 秒内 | >60 次 | **熔断**：将该员工从所有活码移除，30 分钟冷却 |
| 24 小时内 | ≥3 次熔断 | **封锁**：需管理员手动解封 |

**不调用企微 API**。

---

#### 步骤 2：客户入库

**服务**：`CustomerService.upsertFromCallback(externalUserId, userId, state)`

```text
① 从 State 解析 schoolId，查找对应 QrCode
② 按 externalUserId 查找 Customer：
   - 已存在 → 更新 currentAgent / sourceQrId / schoolId，若 deleted 则恢复
   - 不存在 → 调企微 API 获取客户信息，写入新记录
```

**调用企微 API**：✅ `GET /cgi-bin/externalcontact/get?external_userid=xxx`

获取字段：姓名、头像、unionid、客户类型。

---

#### 步骤 3：发布打标事件

**服务**：`TagService`（仅发事件）

```text
XADD 到 Redis Stream: wecom:tag:stream
```

由 `TagWorker` 异步消费（见阶段四）。

**不直接调用企微 API**。

---

#### 步骤 4：日限计数 + 轮换检查

**服务**：`AgentBindService.incrementDailyCount(userId, state)`

```text
① Redis INCR: agent:daily:{userId}:{qrCodeId}  +  agent:daily:total:{userId}
② 设置 TTL 到当天午夜
③ 异步同步到 DB（qr_agent.daily_current / global_agent_pool.daily_current）
④ 三级阈值检查：
```

| 阈值 | 默认值 | 动作 |
|------|--------|------|
| warnRatio | 80% | 仅日志记录 |
| urgentRatio | 95% | 预激活后备员工（提前加入活码，不标记满） |
| 100% | dailyMax | **轮换**：从全局池取后备，标记当前员工 full，通过企微 API 更新活码 |

**调用企微 API**：✅ `POST /cgi-bin/externalcontact/update_contact_way`（轮换时同步活码员工列表）

分布式锁（Redis SETNX 10s TTL）防止并发重复激活。

---

#### 步骤 5：在职继承

**服务**：`TransferService.initiate()`

```text
① 找到活码的服务员工（role=service, status=active）
② 调用企微 API 发起客户转移
③ 检查客户是否已填写采集表
④ 创建 CustomerTransfer 记录（pending_confirm 或 api_failed）
```

**调用企微 API**：✅ `POST /cgi-bin/externalcontact/transfer_customer`

## 阶段四：TagWorker 异步打标

`TagWorker` 从 Redis Stream (`wecom:tag:stream`) 消费，调用 `TagService.autoTag()`：

```text
① 三级地理标签：
   - 城市级标签（如"广州市"）
   - 区县级标签（如"天河区"，父标签为城市）
   - 学校级标签（如"广州市第一中学"，父标签为区县）
   全部归入"家校服务"标签组

② 每级标签：
   - 先查本地 DB 是否存在
   - 不存在 → 调企微 API 创建标签

③ 调企微 API 给客户打标签（传入所有 wecomTagId）

④ 写 CustomerTag 关联记录到本地 DB

⑤ 若活码配置了 customTags，逐个处理逗号分隔的自定义标签
```

**调用企微 API**：
- ✅ `POST /cgi-bin/externalcontact/add_corp_tag` — 创建企业标签
- ✅ `POST /cgi-bin/externalcontact/mark_tag` — 给客户打标签

## 阶段五：定时后台任务

### DailyResetWorker — 每日午夜重置

频率：`@Scheduled(cron = "0 0 0 * * *")`

```text
① 清除 Redis agent:daily:* 键
② GlobalAgentPool: 所有 full → standby，重置 daily_current
③ QrAgent: 所有 full → active，同步到企微（重新加入活码）
④ 生成昨日 DailyReport
```

**调用企微 API**：✅ `POST /cgi-bin/externalcontact/update_contact_way`（同步活码员工列表）

---

### TransferMonitorWorker — 转移结果监控

频率：`@Scheduled(cron = "0 */30 * * * *")`（每 30 分钟）

```text
① 查询状态为 pending_confirm 的 CustomerTransfer
② 调企微 API 查询转移结果
③ 成功 → 确认转移 + 发欢迎语
④ 失败/拒绝 → 标记 rejected
⑤ 超时（>48 次重试，约 24h）→ 标记 timeout
```

**调用企微 API**：
- ✅ `POST /cgi-bin/externalcontact/get_transfer_result` — 查询转移结果
- ✅ `POST /cgi-bin/externalcontact/message/send` — 发送欢迎语

---

### PatrolWorker — 巡逻告警

频率：`@Scheduled(cron = "0 */5 * * * *")`（每 5 分钟）

```text
① 检查全局池后备数量 <5 → alertEmptyBackup 告警
② 检查所有活码员工是否全部 >90% 负载 → traffic_spike 告警
```

**不调用企微 API**。

## 企微 API 调用汇总

| API 端点 | HTTP 方法 | 用途 | 调用时机 |
|----------|-----------|------|----------|
| `/externalcontact/get` | GET | 获取客户详情（姓名、头像、unionid） | 新客户入库时 |
| `/externalcontact/add_contact_way` | POST | 创建活码（联系我二维码） | 管理员创建活码 |
| `/externalcontact/update_contact_way` | POST | 更新活码员工列表 | 轮换激活/每日重置 |
| `/externalcontact/del_contact_way` | POST | 删除活码 | 管理员删除活码 |
| `/externalcontact/transfer_customer` | POST | 发起在职继承 | 客户添加成功后 |
| `/externalcontact/get_transfer_result` | POST | 查询转移结果 | 每 10 分钟轮询 |
| `/externalcontact/message/send` | POST | 发送消息给客户 | 转移成功后发欢迎语 |
| `/externalcontact/add_corp_tag` | POST | 创建企业标签 | 标签不存在时 |
| `/externalcontact/mark_tag` | POST | 给客户打标签 | 自动打标 |
| `/externalcontact/get_corp_tag_list` | POST | 获取企业标签列表 | 标签管理 |
| `/user/simplelist` | GET | 获取部门成员列表 | 员工管理 |

## 关键设计决策

| 决策 | 说明 |
|------|------|
| **Fast Ack** | 回调接口不执行业务逻辑，仅入队即返回，确保企微 5 秒超时前响应 |
| **单线程消费** | CallbackWorker / TagWorker 各为单线程，消除并发问题，简化编码 |
| **Redis Stream** | 消息持久化 + 消费者组 ACK，防止进程重启丢消息 |
| **独立 try-catch** | handleAddSuccess() 每步独立异常处理，一步失败不阻塞其余 |
| **分布式锁** | 轮换激活用 Redis SETNX 10s TTL，防止并发重复激活 |
| **三级熔断** | 告警 → 熔断(30min) → 封锁(需人工)，逐级升级 |
| **access_token 缓存** | 内存缓存 + synchronized 刷新，提前 200s 刷新防过期 |
