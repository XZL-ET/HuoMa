## 0. 一句话结论

- **企微侧的乱没有想象中大**：26… 22 个组里，真正错组的标签是**成体系的几类**（班名散在 学校/年级/学校-甘南州、市名重复进 县区、少量学校进裸「学校」组），另有 2 个「学校-县」异常组和 2 个测试标签。
- **真正的重灾区是本地 `tag` 镜像**：3474 行里 **830 行是重复**，还有 **23 行指向企微已删除的标签**。本地表目前**不是企微的可信视图**，后台按它统计会失真。
- 企微侧「移动标签到正确组」= 删旧 + 建新，会摘掉该标签下所有客户绑定，属于**大工程**（同年级归并套路：先补标再删）。详见 §3。

### 2.1 错组 —— 企微侧（需动企微）

#### 2.1.1 班级/幼班类标签不在「班级」组（14 个）

## 3. 迁移方案（分层，由易到难）

> ⚠ **核心技术约束**：企微里标签归属由「组」决定，**移动标签 = 删旧 + 在目标组建新**，而删除会摘掉 `(成员,客户)` 上该标签的全部绑定。因此凡涉及"换组"的操作，都必须**先给目标标签补打、再删旧标签**（年级归并走过的路）。「改名」则可用 `edit_corp_tag` 原位修改、**保留绑定**。

### S0 —— 本地镜像整理（零企微调用，零客户风险）

纯本地 SQL，让后台视图重新可信：

1. 删 23 行死 wid（2.3.1）。
2. 消 830 行重复：对每个重复 wid，保留 `group_keyword = 企微真实组` 的行，其余删除；空组行可先回填真实组再并。
3. 名不一致 16 行：8 行学期升学**按现状保留**（不动）；2 行学校名补前缀、2 行临夏市→临夏州可一并修。

**影响面**：仅本地 `tag`；`TagService` 有 10 分钟组缓存（`GROUP_CACHE_MINUTES`），改后注意缓存刷新。

### S1 —— 企微命名修正（`edit_corp_tag`，保留绑定）

- 去 ` 西和县第一中学` 前导空格；统一半角括号 → 全角。
- 依赖**属主应用 secret**；若报 `81011 no privilege` → 改用管理后台手工改（见记忆 `wecom-tag-app-ownership`）。

### S2 —— 企微删垃圾（`del_corp_tag`）

- 删 `测试1`（嘉峪关市）、`测试`（临夏州）。
- 本地 6 个 `测试X中` 企微已无，仅需 S0 清本地。

### S3 —— 企微分组归位（大工程：delete + recreate + 重打）

覆盖 2.1.1 / 2.1.3 / 2.1.4 / 2.1.5：

- 14 个班级/幼班类标签 → 迁入 `班级`（与已有同名份合并）。
- 14 个市级名 → 从 `县区` 移除（改由 `市州` 承载）。
- 裸 `学校` 组 85 个学校名 → 按所属市归 `学校-{市}`。
- `学校-榆中县` / `学校-民勤县` → 并入 `学校-兰州市` / `学校-武威市`。
- 同名跨组（育才中学 / 三岔学区 / 榆中县崇文实验学校）→ 判定真属后去重。

**步骤**（每个待迁标签）：
1. **量化**：按目标标签补打前，先全量枚举有多少客户挂着旧标签（`externalcontact/batch/get_by_user` 按员工遍历 1772 成员，约 30 min，一次拿全量）。
2. **补标**：对每个受影响客户 `mark_tag` 打上目标组标签（add-only）。
3. **删旧**：`del_corp_tag` 删旧标签（此时客户已在目标标签上，损失为 0）。
4. **本地重接**：`customer_tag` 的绑定重接到 canonical 行（`CustomerTagInsertService` 的 relink，保留 source/tagged_at）。

**风险**：与年级归并同级；单次企微调用量取决于受影响客户数，需先量化再定批次。

## 6. 执行记录：§4-2 县级学校组并入市组（2026-10-16 完成）

脚本：`docs/ops-scripts/merge_county_school_2_wecom.py`（子命令 check→prepare→census→retag→verify→delete→local）。

**流程与结果**：

1. `prepare`：在 `学校-兰州市` 建 4 个新标签（朝阳/文成/博雅/栖云）；崇文、民勤一中直接 ADOPT 市组已存在的同名份。
2. `census`（全量 1774 成员）：实测各源标签客户数 = 朝阳 834 / 文成 1027 / 博雅 0 / 栖云 3 / 崇文 1096 / 民勤一中 156，合计 **3116**。
3. `retag`：给这 3116 条 (客户,成员) 关系补打目标标签，**3116 OK**。
4. `verify`：全量复枚举，发现 1 个「带源不带目标」（census 之后被新打的）→ 补打其 2 条关系 → 重跑 verify，**MISSING=0**。
5. 6 个旧标签 **81011**（非本应用创建，三套 secret 皆拒），由**管理员在企微管理后台手工删除**；删后两个县组消失。
6. `local`：本地镜像按 wid 重接（**不按组名** —— 绑定常挂在错标行上），6 个旧 wid 行清零，绑定保留到新 wid 行。

**遗留 / 注意**：

- 企微侧「移动标签」= 建新 + 补标 + 删旧，无法原子；旧标签存活期间成员仍可继续打（本次就冒出 1 个），故 verify 干净后应**尽快**删除旧标签。
- 本地 `tag` 表的 **830 行重复 / 23 行死 wid**（§2.3）**未动** —— 属 S0，另行处理。
- §2.1 其余错组（班级、县区市名、裸学校组、命名）**未动** —— 属 S3 / S1 / S2。
